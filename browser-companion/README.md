# Experimental normal-browser checkout companion

This separate local Chrome/Edge Manifest V3 extension previews a narrow merchant checkout snapshot in a tab the user navigates themselves. It is **not integrated with Flight Finder**, does not update its prices/history, does not apply coupons, and never purchases a ticket. Unsupported layouts return unverified evidence.

Load this folder using the browser's Extensions → Developer mode → Load unpacked. Open an ordinary provider tab, navigate manually, click this extension, and enter the intended itinerary. The popup performs two read-only captures one second apart and previews structured JSON locally. Nothing is submitted or saved automatically.

`activeTab` grants temporary tab access after a user gesture. `scripting` runs a self-contained reader in Chrome's default isolated world. There are no persistent host permissions, cookie/storage/network/clipboard permissions, content scripts, background workers or external messaging. Extension page CSP forbids network connections. The reader allows only explicit EaseMyTrip, Cleartrip and MakeMyTrip HTTPS hostnames, scans one visible booking-summary container with at most 300 fields, ignores personal-field containers and all form values, and returns only canonical trip checks, INR total/fees and payment-method/bank categories. Source URL queries and booking identifiers are never returned. It does not inspect gateway frames.

The supported payment-summary selectors are a conservative prototype contract, **not layouts validated on real payment pages**. Local fixture tests establish parsing/privacy rejection behavior. Payment snapshots require an explicit directed route, full ISO date/year, flight number/time, adult count, cabin, selected payment category, and matching visible Pay-control amount. Unknown or conflicting evidence fails closed. Even a stable complete snapshot has `usable_as_final_price=false` and `eligible_for_learning=false`: subsequent gateway/bank charges remain unknown, coupon eligibility is not verified, and a page or modified browser can forge DOM evidence.

A separate Cleartrip review reader was added after a real ordinary-browser test reached the itinerary page. It uses semantic headings and at most 500 descendants in the itinerary section, reads observed airports/date/year/flight/times/adults, the INR review total and visible coupon tags. Its extraction logic was checked against the actual page; boundary/privacy tests use small local fixtures, not saved page dumps. It always returns `review_partial`, `criteria_match=false`, and both final-price/learning flags false: the observed page shows a fare family, which cannot establish cabin or selected payment. The extension itself has not been installed or tested end to end on that real page. A manual CTBBD trial reduced BLR–LKO, 23 February 2027, QP1521 from INR 6,785 to 6,344 at review; the reader does not infer coupon acceptance from a tag.

This can avoid differences introduced by creating a new automation browser/profile, because it reads the browser the user already uses. It cannot force a provider to allow access, bypass verification, establish arbitrary payment-frame contents, or give unattended monitoring access after its user gesture expires. Cleartrip review access worked in the ordinary in-app browser while fresh Chromium failed, but integrated companion checkout recovery and MakeMyTrip recovery remain **unproven**.

A production integration needs a one-use expiring pairing token bound to exact trip/search and provider origin, local-only message transport with explicit UI invocation, schema/size/freshness validation, independent backend identity checks, disposable capture tests on actual supported layouts, and a separate manual-evidence status. Uploaded JSON must not automatically become trusted learning data. Native messaging adds installation/maintenance; broad `externally_connectable` or host permissions would widen attack surface. Neither is included here.

Official documentation: [activeTab](https://developer.chrome.com/docs/extensions/develop/concepts/activeTab), [scripting](https://developer.chrome.com/docs/extensions/reference/api/scripting), [isolated content-script worlds](https://developer.chrome.com/docs/extensions/develop/concepts/content-scripts), [messaging security](https://developer.chrome.com/docs/extensions/develop/concepts/messaging#security-considerations).
